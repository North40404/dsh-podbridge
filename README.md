# dsh-podbridge

> 本文件是**仓库门面**：这个项目是什么、怎么组织。插件安装与配置细节见 [`plugin/README.md`](plugin/README.md)。


Pod App 与 DSH 会话之间的桥接：把聊天消息投进会话，把回复推回聊天软件。

## 它做什么

```
手机/桌面客户端 ──HTTP──► 桥接 ──投递──► DSH 会话
                            ◄──推送──
```

- **下行**：SSE（`GET /events?since=&token=`），服务端主动推 `msg`
- **上行**：`POST /send`、`POST /upload`、`GET /history`
- **聚合**：同一波消息在静默窗口内合并成一次投递，避免模型被逐条打断
- **文件**：上传落到磁盘，客户端按 id 取回；协议里定义了消息的 `attachments`

## 与"触发类"插件的边界

**本插件拥有消息路径（收消息、决定回不回），触发类插件拥有触发路径（什么时候叫醒模型）。**

两者互不知道对方。它们做的事其实一样——"往会话里投一条消息"——
所以停用任何一个，另一个照常工作。

## 协议要点

- 通道：**SSE 下行 + POST 上行**（不是 WebSocket；早期试过，本地 link 安装解析不到 `ws`）
- 鉴权：一次性配对码换长期 token；`/events`、`/send`、`/files` 都要 token
- `seq` 由服务端分配、单调递增，**客户端不得自造**
- 附件**不强制**服务端长期保留，但客户端会依赖 `/files/<id>` 作为本地副本丢失后的退路

## 警告

这套东西会把一个会话**暴露到网络**。部署时至少要：

- 桥接自己跑在 `127.0.0.1`，用 frp / SSH 反向隧道 / Tailscale 之类把外部端口转进来
- 配对码不要外传；token 泄露等于对方能读你所有聊天记录
- 别把 8787 直接映射到公网裸奔（虽然有 token，但没有 TLS）
