# dsh-podbridge

> 本文件是**仓库门面**：这个项目是什么、怎么组织。插件安装与配置细节见 [`plugin/README.md`](plugin/README.md)。


把聊天客户端与 DSH 会话接起来：客户端发的消息投进会话，会话的回复推回客户端。

> Pod App 是配套的参考客户端；本插件不依赖它的实现——任何符合《Pod 桥接协议 v1》的客户端都能接。

## 它做什么

```
手机/桌面客户端 ──HTTP──► 桥接 ──投递──► DSH 会话
                            ◄──推送──
```

- **下行**：SSE（`GET /events?since=&token=`），服务端主动推 `msg`
- **上行**：`POST /send`、`POST /upload`、`GET /history`
- **聚合**：同一波消息在静默窗口内合并成一次投递，避免模型被逐条打断
- **文件**：上传落到磁盘，客户端按 id 取回；协议里定义了消息的 `attachments`

## 与"触发类"插件的边界

**本插件拥有消息路径（收消息、决定回不回），触发类插件拥有触发路径（什么时候叫醒模型）。**

两者互不知道对方。它们做的事其实一样——"往会话里投一条消息"——
所以停用任何一个，另一个照常工作。

## 协议要点

- 通道：**SSE 下行 + POST 上行**（不是 WebSocket；早期试过，本地 link 安装解析不到 `ws`）
- 鉴权：一次性配对码换长期 token；`/events`、`/send`、`/files` 都要 token
- `seq` 由服务端分配、单调递增，**客户端不得自造**
- 附件**不强制**服务端长期保留，但客户端会依赖 `/files/<id>` 作为本地副本丢失后的退路

## 警告

这套东西会把一个会话**暴露到网络**。部署时至少要：

- 桥接自己跑在 `127.0.0.1`，用 frp / SSH 反向隧道 / Tailscale 之类把外部端口转进来
- 配对码不要外传；token 泄露等于对方能读你所有聊天记录
- 别把 8787 直接映射到公网裸奔（虽然有 token，但没有 TLS）

**关于链路加密**：本插件默认是 `http://`（无 TLS）。token 只做认证，**不加密内容**——
链路上的设备（VPS、家宽端口映射后的公网路径、公共 Wi-Fi）都能看到报文，**包括 token 和消息正文**。

按你的威胁模型选：

| 做法 | 挡得住谁 | 挡不住谁 |
|---|---|---|
| 隧道层 TLS（frp `transport.tls`） | 链路上的随机旁观者、公共 Wi-Fi | **中转服务器本身**（它解密后才转发） |
| SSH 反向隧道 | 同上 | 同上 |
| WireGuard / Tailscale | 上面全部 + **中转方也看不到** | —（要装客户端） |

**特别提醒**：把 8787 直接映射到**家宽公网 IP** 是最危险的做法——
既没有隧道加密，又让整个互联网都能扫到端口（只能靠 token 兜底）。
至少要配 HTTPS 反代，或者用隧道/覆盖网。

## 术语：谁是"服务端"

文中说的**服务端**，指**运行在你自己电脑上的这个桥接插件**（默认 `127.0.0.1:8787`）。

| 角色 | 是什么 | 在协议里做什么 |
|---|---|---|
| **服务端** | 本插件（你的电脑） | 发 token、推 `msg`、存文件、执行配对 |
| 中转（可选） | VPS 上的 frp / SSH 隧道 | **只转发 TCP 字节**，不解析协议、不认 token、没有 `/events` |
| 客户端 | Pod App 或任何符合协议的实现 | 发消息、收推送 |

所以：**"服务端"从来不是 VPS**。没有中转时客户端也可以直连（同一局域网），
有中转只是为了让外网也能连到同一台电脑。

## 发文件：两条路（务必读完）

本插件提供两种把本地文件推到客户端的方式。两者共用同一份白名单与大小上限实现
（`deliverLocalFile()`），区别只在"谁能调用"。

| 路径 | 给谁用 | 为什么需要它 |
|---|---|---|
| 工具 `pod_send_file` | 模型在对话里发文件 | 自然、不需要 shell |
| `POST /api/dsh-podbridge/send-file` | 脚本、定时任务、**没有工具调用的场景** | 工具要模型主动调，端点给"程序自己发"用，见下 |

### 工具 `pod_send_file` 的注意事项

1. **插件重载后，新工具会进入已存在的会话**（实测：本插件中途新增的 `pod_send_file`，
   在早已运行的会话里可以直接调用）。所以"改了工具要新开会话"是**错的**，重载就够。
2. **真正会让工具"看不见"的是两个开关**：
   - `when` 返回 false → 工具**静默隐藏**，不报错，很难察觉；
   - `deferLoading: true` → schema 不进当轮上下文，等于不可达。
   本插件两者都不用；权限校验放在 `execute` 里显式抛错，比静默隐藏好排查。
3. **注册为全局**：所有会话都看得到，但 `execute` 里校验 `agent.id === settings.sessionId`，
   非绑定会话调用会得到明确报错。
4. **路径白名单**：默认允许绑定会话的 cwd、下载目录、插件自己的文件目录；
   开关是设置页的「文件白名单」，**默认权限下模型改不到**（配置在工作区外的 `~/.dsh`）。
   这是权限边界而非绝对保证：拿到完全文件权限、或把插件装进工作区的场景下，模型仍能直接改配置。
5. 超过 `maxBytes` 会直接拒绝。

### 端点默认是**关闭**的

设置页有一个开关「**开放发文件端点（HTTP）**」，默认不勾。原因是它属于兜底通道：
正常对话里 agent 用工具就够了，而开着它等于在本机管理面上多一个"能把白名单内文件推到手机"的入口。

**什么时候需要打开它**：

- 调用方是**脚本 / 定时任务 / 服务**：它们没有模型，调不了工具，只能走 HTTP。
- 需要在**不改动对话**的情况下推文件（例如别的程序产生文件后直接丢给手机）。

> 注：早期版本这里写过"老会话看不到工具所以要用端点"——那个结论是**错的**，
> 插件重载后工具会进入已存在会话。端点保留的理由是"没有模型的场景"，不是"工具不可见"。

开关是**热生效**的：改完立刻起作用，不需要重载插件。关闭后端点返回
`403 {ok:false, error:"endpoint_disabled"}`。

### HTTP 端点的注意事项

1. **它挂在 DSH 的 web 端口上，不是桥接的 8787**。
   8787 只有数据面：`/health`、`/events`、`/send`、`/upload`、`/files/<id>`。
   打到 8787 会 404。
2. **没有鉴权**，和所有 `/api/dsh-podbridge/*` 管理端点一样，靠的是「DSH web 只监听 127.0.0.1」。
   **不要把这个端口暴露到公网。** 需要外网访问时，暴露的应当只有 8787（数据面，有 token）。
3. 请求体：`{"path": "<绝对路径>", "caption": "可选说明"}`；
   成功返回 `{ok,name,size,mime,id}`，失败返回 400 + `{ok:false,error}`。
4. **它不属于 Pod 协议**：协议 v1 没有定义"服务端主动推送文件"，所以换一个桥接实现就没有这个端点。
   它属于本插件的便利设施。
